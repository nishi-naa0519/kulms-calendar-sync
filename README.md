# KULMS Calendar Sync

京都大学の学習支援システム **KULMS** の課題締切を、**Google カレンダー**に自動で同期する Chrome 拡張機能です(試験版 v0.5)。

> [!WARNING]
> 本ツールは**京都大学および情報環境機構の公式ツールではありません**。個人が学習目的で作成したもので、大学から提供・承認・保証されたものではありません。利用前に必ず「[免責事項・注意事項](#免責事項注意事項)」を読んでください。

---

## できること

- KULMS を Chrome で開くと、自分の課題一覧を取得して Google カレンダーに予定を作成します。
- 予定は**提出締切のちょうど 24 時間前**から **5 分間**の予定として作成します。
- 予定のタイトルは**授業名**、説明欄には**課題名と本当の提出期限**が入ります。
- 予定の色は Google カレンダーのイベントラベル **「マンゴー」** を使います。
- 同じ課題を何度同期しても予定は重複しません。締切が変更されたら既存の予定を更新します。
- 次のどちらかを満たすと、その課題の予定を自動で削除します。
  1. KULMS で本当に提出した
  2. 提出していなくても締切を過ぎた
- KULMS の ID・パスワード・多要素認証の情報や、認証 Cookie の値は**一切読み取らず、保存しません**。
- 外部サーバーは使いません。通信先は KULMS と Google Calendar API だけです。

---

## 動作要件

- Google Chrome(デスクトップ版)
- 京都大学の学生アカウント(ECS-ID)で KULMS にログインできること
- Google アカウント
- Google Cloud のプロジェクトを自分で作成できること(無料。クレジットカード登録は不要)

> [!NOTE]
> このリポジトリには OAuth の Client ID が含まれていません。Google Calendar API を使うために、**利用者ごとに自分の Google Cloud プロジェクトと OAuth クライアントを作成する必要があります**。手順は次の「初回セットアップ」で説明します。

## 初回セットアップ

全体の流れは次のとおりです。順番が大切なので、上から順に進めてください。

```text
1. ソースコードを取得する
2. Chrome に読み込んで「拡張機能 ID」を確認する
3. Google Cloud プロジェクトを作成し、Calendar API を有効化する
4. OAuth 同意画面(Google Auth Platform)を設定する
5. OAuth クライアント(Chrome 拡張機能)を作成する
6. manifest.json に Client ID を書き込む
7. Google カレンダーに「マンゴー」ラベルを用意する
8. 拡張機能から Google アカウントを接続して同期する
```

### 1. ソースコードを取得する

```bash
git clone https://github.com/nishi-naa0519/kulms-calendar-sync.git
```

または GitHub の「Code → Download ZIP」でダウンロードして展開します。

> [!IMPORTANT]
> 展開したフォルダは、**今後移動・削除しない場所**に置いてください(例: `C:\Users\<ユーザー名>\tools\kulms-calendar-sync`)。
> 開発用に読み込んだ拡張機能の ID はフォルダの場所から決まるため、あとでフォルダを移動すると ID が変わり、手順 5 の OAuth 設定をやり直す必要があります。Downloads フォルダは誤って削除しやすいので避けるのがおすすめです。

### 2. Chrome に読み込んで拡張機能 ID を確認する

1. Chrome のアドレスバーに `chrome://extensions` と入力して開きます。
2. 右上の **「デベロッパー モード」** をオンにします。
3. **「パッケージ化されていない拡張機能を読み込む」** を押し、リポジトリ内の `kulms-calendar-sync` フォルダ(`manifest.json` が入っているフォルダ)を選びます。
4. 「KULMS Calendar Sync」のカードに表示される **ID**(32 文字の英小文字。例: `abcdefghijklmnopabcdefghijklmnop`)をメモします。

この時点では Client ID が未設定なので、Google 接続はまだ動きません。

### 3. Google Cloud プロジェクトを作成し、Calendar API を有効化する

1. [Google Cloud Console](https://console.cloud.google.com/) を開き、Google アカウントでログインします。
2. 画面上部のプロジェクト選択から **「新しいプロジェクト」** を作成します。名前は自由です(例: `kulms-calendar-sync`)。
3. 作成したプロジェクトが選択されていることを確認します。
4. 左上のメニュー → **「API とサービス」 → 「ライブラリ」** を開きます。
5. **「Google Calendar API」** を検索し、**「有効にする」** を押します。

### 4. OAuth 同意画面(Google Auth Platform)を設定する

左上のメニュー → **「Google Auth Platform」** を開きます(初回は「開始」ボタンから設定を始めます)。

1. **Branding(ブランディング)**
   - アプリ名: 任意(例: `KULMS Calendar Sync`)。Google の同意画面に表示されます。
   - ユーザーサポートメール / デベロッパーの連絡先: 自分のメールアドレス
2. **Audience(対象)**
   - ユーザーの種類: **External(外部)**
   - 公開ステータス: **Testing(テスト)** のままにします。
   - **テストユーザー** に、カレンダーを同期したい**自分の Google アカウント**を追加します。追加していないアカウントでは認可できません。
3. **Data Access(データアクセス)**
   - 「スコープを追加または削除」から、次の 2 つを追加して保存します。
     - `https://www.googleapis.com/auth/calendar.events`
     - `https://www.googleapis.com/auth/calendar.calendars.readonly`

### 5. OAuth クライアント(Chrome 拡張機能)を作成する

1. Google Auth Platform の **「Clients(クライアント)」** → **「クライアントを作成」** を押します。
2. アプリケーションの種類: **「Chrome 拡張機能」** を選びます。
3. 名前: 任意(例: `KULMS Calendar Sync (local)`)
4. **アイテム ID**: 手順 2 でメモした**拡張機能 ID** を入力します。
5. 作成すると **クライアント ID**(`xxxxxxxxxxxx-xxxxxxxx.apps.googleusercontent.com` の形式)が表示されるので、コピーします。

> [!NOTE]
> Chrome 拡張機能のクライアントには「クライアント シークレット」は不要です。拡張機能のコードは誰でも読めるため、秘密情報を埋め込まない設計になっています。

### 6. manifest.json に Client ID を書き込む

`manifest.json` の次の行を、手順 5 でコピーしたクライアント ID に書き換えます。

```json
"client_id": "REPLACE_WITH_YOUR_CLIENT_ID.apps.googleusercontent.com",
```

```json
"client_id": "123456789012-abcdefghijklmnopqrstuvwxyz012345.apps.googleusercontent.com",
```

保存したら `chrome://extensions` に戻り、「KULMS Calendar Sync」の **更新ボタン(⟳)** を押して読み込み直します。

> [!CAUTION]
> 自分の Client ID を書き込んだ `manifest.json` を、フォークなどで公開リポジトリに push しないようにしてください。Client ID 自体は秘密情報ではありませんが、あなたの Google Cloud プロジェクトと結びついた値です。

### 7. Google カレンダーに「マンゴー」ラベルを用意する

この拡張機能は、予定の色として **「マンゴー」という名前のイベントラベル**を使います。

1. [Google カレンダー](https://calendar.google.com/) を開きます。
2. 同期先のカレンダー(通常はメインのカレンダー)で、**「マンゴー」という名前のイベントラベル**を作成します。

ラベルが見つからない場合、同期時に「マンゴーのイベントラベルが見つかりません」というエラーになり、予定は作成されません(勝手に別の色を使わず、設定漏れを知らせるための仕様です)。

### 8. Google アカウントを接続して同期する

1. Chrome のツールバーにある拡張機能アイコンから **「KULMS Calendar Sync」** を開きます(パズルのピース型アイコンからピン留めしておくと便利です)。
2. **「Google アカウントを接続」** を押します。
3. Google の画面が開くので、手順 4 でテストユーザーに追加したアカウントを選びます。
4. 「Google hasn't verified this app(このアプリは Google で確認されていません)」と表示されたら、**自分で作成したアプリであることを確認したうえで**「続行」を押します。テスト中のアプリでは正常に表示される警告です。
5. 要求される権限(カレンダーの予定の表示・編集、カレンダー設定の閲覧)を確認して許可します。
6. 別のタブで [KULMS](https://lms.gakusei.kyoto-u.ac.jp/portal) を開き、いつもどおり大学のアカウントでログインします。
7. ポップアップで **「今すぐ同期」** を押します。
8. ポップアップの「状態」欄で `"state": "success"` になっていること、Google カレンダーに予定ができていることを確認します。

以降は、**KULMS を開くだけで自動的に同期**されます。

> [!TIP]
> 最初は、テスト用に作った別の Google カレンダーで動作を確認するのがおすすめです。ポップアップの「同期先カレンダーID」に、Google カレンダーの「設定 → カレンダーの統合」に表示されるカレンダー ID を入力して「設定を保存」を押すと、同期先を変更できます。

## 使い方

### 自動同期のタイミング

| タイミング | 処理 |
|---|---|
| KULMS のポータルを開いたとき(前回のフル同期から 5 分以上経過) | フル同期(課題一覧の取得・予定の作成/更新/削除) |
| KULMS のポータルを開いたとき(前回のフル同期から 5 分以内) | 提出状態のチェックのみ(10 秒に 1 回まで) |
| 管理中の予定のうち最も早い締切の直後 | 締切を過ぎた予定の削除(`chrome.alarms`) |
| Chrome の起動時・拡張機能のインストール/更新時 | 締切を過ぎた予定の削除 |

KULMS への負荷を抑えるため、フル同期には 5 分のクールダウンがあります。

### 授業名が取得できない場合

授業名は KULMS の `/direct/site/{授業ID}.json` から取得します。取得できなかった授業の ID は、ポップアップの「状態」欄の `missingCourseIds` に表示されます。その場合は「授業名の上書き(JSON形式)」に次の形式で入力し、「設定を保存」を押してください。

```json
{
  "授業ID": "授業名"
}
```

## 予定の作成・削除ルール

### 作成ルール

- `/direct/assignment/my.json` から自分の課題一覧を取得します。
- 締切は `dueTime.epochSecond` / `dueTime.nano` を使います。
- 締切ちょうど 24 時間前から 5 分間の予定を作成します。
- タイトルは授業名、説明欄は課題名と提出期限です。
- 課題 ID・授業 ID・締切を予定の `extendedProperties.private` に保存し、同じ課題の予定を見つけるために使います。
- 締切が変更された場合は、同じ予定を更新します。
- すでに締切を過ぎた課題や、提出済みの課題の予定は作成しません。

### 削除条件

この拡張機能が作成した予定(`extendedProperties.private.kulmsManaged=v1` を持つもの)**だけ**が削除の対象です。手動で作成した予定や、他のアプリが作成した予定は削除しません。

次の**どちらか**を満たすと削除します。

1. **本当に提出した**: KULMS の提出 API (`/direct/assignment/itemSubmission/{課題ID}.json`) で、次の 3 つをすべて確認できた。
   - `submitted` が `true`
   - `draft` が `true` ではない
   - 実際の提出日時がある(`dateSubmittedEpochSeconds > 0`、または解析可能な `dateSubmitted`)
2. **締切を過ぎた**: 予定に保存した締切(`kulmsDue`)を現在時刻が過ぎた。

KULMS では、未提出・未開始の課題でも `submitted: true` が返ることがあります。そのため `submitted` だけでは提出済みと判断せず、提出日時の存在も必須にしています。

提出 API がエラーを返したり、応答の形式が想定と違ったりして提出状態が分からない場合は、**提出済みとは扱わず、予定を残します**。未提出の課題の予定を誤って消すより、提出済みの予定が締切まで残るほうを安全と考えています。

## 要求する権限

| 権限 | 用途 |
|---|---|
| `webNavigation` | KULMS のページを開いたことを検知して自動同期を始める |
| `storage` | 設定と最後の同期結果を Chrome 内に保存する |
| `identity` | Google の OAuth で Calendar API 用のアクセストークンを取得する |
| `alarms` | 締切時刻に予定の削除処理を予約する |
| `https://lms.gakusei.kyoto-u.ac.jp/*` | ログイン中のブラウザのセッションで KULMS の課題 API を呼ぶ |
| `https://www.googleapis.com/*` | Google Calendar API を呼ぶ |

Google OAuth のスコープは、必要最小限の次の 2 つだけです。

| スコープ | 用途 |
|---|---|
| `calendar.events` | 予定の一覧取得・作成・更新・削除 |
| `calendar.calendars.readonly` | 「マンゴー」ラベルの ID をカレンダー設定から読み取る |

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 「Google認証が必要です」と表示される | Google 接続が切れています。ポップアップの「Google アカウントを接続」を押し直してください。下の「7 日ごとに再接続が必要」も参照してください。 |
| 「Google アカウントを接続」でエラーになる | `manifest.json` の Client ID が正しいか、OAuth クライアントのアイテム ID が `chrome://extensions` に表示されている拡張機能 ID と一致しているか、使った Google アカウントがテストユーザーに入っているかを確認してください。 |
| 「KULMSはJSON以外を返しました」と表示される | KULMS のログインが切れています。KULMS を開いてログインし直してください。 |
| 「マンゴーのイベントラベルが見つかりません」と表示される | 同期先カレンダーに「マンゴー」ラベルがありません。初回セットアップの手順 7 を確認してください。 |
| 特定の授業の課題だけ予定ができない | 授業名が取得できていない可能性があります。「授業名が取得できない場合」を参照してください。 |
| フォルダを移動したら動かなくなった | 拡張機能 ID が変わっています。新しい ID を OAuth クライアントのアイテム ID に登録し直してください。 |

## 制限事項

- **7 日ごとに再接続が必要**: Google Auth Platform の公開ステータスが Testing のアプリでは、ユーザーの認可がおよそ 7 日で失効します。失効したら「Google アカウントを接続」を押し直してください。
- **Chrome が動いていないと処理されない**: 外部サーバーを使わない設計のため、Chrome の終了中や PC のスリープ中は同期・削除が行われません。Chrome が再び動き始めた後に処理されます。`chrome.alarms` は締切ちょうどの削除を保証するものではありません。
- **KULMS を開かないと新しい課題は同期されない**: 新しい課題の取得は、KULMS のページを開いたときに行われます。
- **KULMS の仕様変更で動かなくなる可能性がある**: 本ツールが使う KULMS(Sakai)の Direct API は、大学が学生向けに公開・保証しているものではありません。
- 京都大学 KULMS(`lms.gakusei.kyoto-u.ac.jp`)専用です。
